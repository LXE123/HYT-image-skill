# 产品图片技能通用证据设计

本方案面向产品建包、单图生成和 Amazon 套图三个技能，覆盖单张模糊图、未拆包装实拍、多视角照片及带渲染模板的输入。统一采用“先保存资料与不确定性，再按图片任务判断是否可生成”的机制。通用性来自证据处理和任务判断，不来自预置某款产品的结构。

状态：设计方案，尚未实现。以下新增字段和行为均为拟议接口；当前脚本仍执行原规则。方案不承诺从缺失信息中恢复真实结构，也不以生成次数或脚本通过替代实图验证。

## 一 核心决策

必须分开三个结论：

| 结论 | 回答的问题 | 不代表什么 |
| --- | --- | --- |
| 工程有效 | 原始资料、来源和分析记录是否完整可读、相互一致 | 产品所有结构已经确定 |
| 当前任务可生成 | 本图必需的事实、视角和状态是否有足够依据 | 图像模型一定遵守约束 |
| 候选图通过检查 | 实际输出是否符合当前任务与原始证据 | 未展示或未获证实的结构正确 |

弱输入可以形成有效工程；缺口可以阻止一张图片，却不应阻止整个工程保存或其他有依据的任务。输入损坏、路径越界、哈希错误等工程问题仍直接报错，不能用“资料不足”掩盖。

证据来源方式与证据充分程度分开。保留 `MODEL_ASSISTED` / `PHOTO_EVIDENCE` 表示当前生产依据，停止把 `INCOMPLETE` 当作第三种来源模式；不足记录在现有 baseline 和 gaps 中。初始化允许暂不确定生产模式，在首次生成前根据实际来源确定；不能将来源不明的图片登记为实拍。只有文字时也可保存 intake 工程，但真实产品图片生成仍需要足以约束身份与本图关键结构的视觉证据。

## 二 最小工程

沿用现有工程和临时存储规则，不新建轻量技能或另一套产品数据库。未知 ID 使用临时任务身份，不猜测 SKU。初始化只做无损保存与空记录创建，随后由 AI 看原图、读描述并完成语义分析。

| 现有位置 | 职责 | 弱输入处理 |
| --- | --- | --- |
| `input/01_product_evidence/` 等原始资料目录 | 保存实际附件 | 模糊、包装和遮挡都保留原样，不先“修清晰”再当原证据 |
| `index.json` | 文件身份、来源、视角、可支持范围 | 可保存待分析资料；没有可确认结构时允许覆盖为空，不伪填 `full_product` |
| 现有 intake JSON 的 `product.facts` | 原子事实与文字来源 | 保留原文、依据和支持范围，未确认条目不导出成已支持事实 |
| `PRODUCT_STATE.json` | 产品边界、baseline、结构锁、缺口与流程 | 允许局部已知与未知共存；登记完成不自动将全部身份标成就绪 |
| 当前合同或逐图任务 | 本图必需事实、选中证据和限制 | 有任务时再建立；仅整理资料无需初始化生成合同 |

对每个输入完成一次基础分析即可建包，不要求穷举所有隐藏结构。新增任务涉及先前未检查区域时，再分析所需证据并补充记录。裁剪、锐化、去背景等派生图须指回原图；它们既不是独立视角，也不增加原图未提供的信息。

## 三 记录事实的来源与适用范围

采用三种互不替代的信息：可从图像观察的事实、用户或规格明确提供的事实、尚待验证的推测。推测不能进入生产事实，也不能由生成图反向升级为实物证据。图像和描述冲突时保存冲突，不按来源排序机械覆盖；涉及当前关键事实时暂缓该任务。

每个事实应能回答“说了什么、谁提供或在哪看见、对什么范围有效”。拟在现有事实条目上增补来源引用与适用范围，而非再建全局置信度分数：

```json
{
  "fact_id": "clasp_present",
  "text": "表带具有一个扣具",
  "status": "SUPPORTED",
  "provenance": [
    {"kind": "USER_STATEMENT", "source_ref": "intake:user-description-01"}
  ],
  "support_scope": "仅确认存在；未确认扣具几何、连接方式或开合动作"
}
```

此例中的 `SUPPORTED` 只支持这句话，不能因为它存在就批准扣具特写或穿带路径。视觉事实的 `provenance` 应引用已登记的证据 ID 和可定位区域；区域可以用文字描述，只有需要精确定位时才增加坐标。尺寸、材质、颜色和操作声明分别核实，不能用外观相似替代。

拟在证据条目增加可选的 `observations`，用于记录每个区域的对象角色、观察结果、限制及其影响，例如“右上角塑料封边属于包装，不支持扣具轮廓判断”。实际实拍可继续是 `hard_constraint: true`，但硬约束只适用于它能证明的事实，不能将整张图的所有像素都解释成产品属性。

缺口复用 `evidence_gaps`：说明未知或冲突的事实、原因、受影响任务，以及能解决它的最小补充。只登记与产品识别或当前工作有关的缺口，不为每款产品生成完整拍摄清单。

## 四 包装与拍摄干扰

先区分售卖主体、随售配件、拍摄道具、运输包装和保护膜；同一透明壳可能属于不同角色，不能默认删除。“随售包装”与“本图要不要展示”分别判断。身份无法确定且影响任务时，只询问这一处。

按区域和事实使用资料，不按整张照片二选一：

| 干扰 | 可以保留的依据 | 不能推出的事实 |
| --- | --- | --- |
| 透明吸塑壳 | 未明显受折射和遮挡影响的部件关系 | 将封边、高光或壳轮廓当成产品结构 |
| 保护膜和反光 | 仍可辨认的孔位或连接位置 | 真实表面光泽、精确颜色和微纹理 |
| 包装挤压软质产品 | 可辨认的部件数量和连接关系 | 拆包后自然形态及准确比例 |
| 标签和不透明遮挡 | 未遮挡区域的明确事实 | 遮挡下的接口、标识和扣合方式 |
| 模糊或低分辨率 | 仍然可辨认的宏观信息 | 锐化后新增的纹理或小零件是真实细节 |

识别包装不等于能还原拆包产品。去掉包装若必须重建未知结构，就按缺证据任务处理。拍摄的光照、透视和姿态变化也按相同机制记录其影响，无需为每类异常增加一种工程模式。

## 五 按任务决定准入

复用 `required_fact_ids`、`must_show`、目标视角、结构检查和操作状态。单图与套图应调用同一证据判断规则，不分别定义宽松版本。

判断顺序：

1. 明确当前任务必须表达的内容，区分画面事实、文案事实与可选创意。
2. 列出画面实际会出现的关键结构，以及表达动作或接触关系所需的物理条件。不能只看 `required_fact_ids` 是否填齐；佩戴图的穿带路径、可见扣具等仍需检查。
3. 对照当前 SKU 的原始资料，核对覆盖、清晰度、干扰、状态与事实冲突。任意视角图不自动支持同一 SKU 的其他视角。
4. 得到以下结果，并保存在当前合同/任务的拟议 `evidence_assessment` 中。此结果绑定任务和所用事实/证据快照，不另设全局就绪清单。

| 结果 | 条件 | 执行 |
| --- | --- | --- |
| `READY` | 当前任务所有关键依赖有依据，未解决缺口不影响本图 | 固定适用范围，生成候选；仍须 QA |
| `REPLAN` | 现方案不成立，但能在用户任务范围内换一种有依据的表达 | 修订视角、动作或表现方式，再检查依赖；不能直接当就绪 |
| `NEEDS_EVIDENCE` | 必需结构或内容没有依据，且改表达会丢失用户必需职责 | 保留任务和具体缺口，继续其他可执行工作 |

“原视角”只是降低新增未知的机会，不是自动准入条件。若该视角本身就看不清关键结构，仍不能通过。缩小产品、刻意遮住结构、改成纯文案不能用来绕过本图必需职责；用户明确要求扣合示意时，不把外观图算成完成。

AI 可自主调整可逆创意；用户固定的视角、动作、原文和已固定计划按现有修订规则处理。需要补证据时合并一次询问，说明具体缺口，例如“扣具打开后连接两端的照片”，不泛泛索要更多照片。

## 六 结构锁与生成交接

结构锁锁定当前产品有依据的事实，不是全品类结构模板。不同扣合方式使用相同记录机制，但锁内容分别来自本款证据。没有依据时不填扣型、不推断运动路径；品类知识只能辅助提出待验证假设。

拟给结构锁增加直接来源引用：事实 ID、证据 ID、适用视角/状态和约束范围。现有渲染模板锁和锚点锁继续有效，但不再要求所有照片事实都先产出灰度图和轮廓图才能生成。高风险局部确需锚点时再提取；从模糊源图生成轮廓资产不能消除不确定性。

`identity_lockset` 的版本继续负责一致性；其 `READY` 表示所登记的锁有有效依据，不能代表整件产品的所有结构已知。每张图的 `required_lock_ids` 必须逐一匹配本图关键事实；没有可用身份/结构依据的真实产品任务不能通过空锁集合绕过准入。

生成工具只收到当前图所需的原始证据、适用锁、当前设计和限制；实际附件必须传入。包装区域保留必要的角色说明。不能只写“保持结构准确”，而要写明本图需要保持的具体事实及不可扩展的视角/状态。候选图、风格图、通用线稿均不得补充未知产品几何。

直接保留产品像素并做背景合成可作为另一个有条件的执行选择，但本次设计不将其默认接入：当前技能尚未提供该生产路径，且现有导出说明不授权源照片拼贴。后续启用时须确认工具确实保留了哪些像素、分辨率是否够用、是否影响任务；生成式编辑不能冒称产品像素未变。它也不能补出遮挡结构。

## 七 验收与套图执行

沿用现有视觉 QA、人工接受和有限重试机制。每个关键检查项必须同时具备可比较的原始依据和对实际候选的观察。`PASS` 表示该项有依据且输出一致；输出明确不一致为失败；依据不足或看不清为不确定，不得记为通过。

任务不涉及的背面结构无需检查，但候选若额外露出未知背面，必须识别为新增风险，修图或重新规划。若生成过程改变了关键结构，回到原始证据纠正；模型重试和自查不能补充实物真值。人工接受保留真实反馈来源，也不自动消除未知事实。

套图逐个子任务准入和执行，不因某个扣具特写缺证据而阻断已就绪外观图；也不把暂缓图静默删掉或替换成重复画面凑数。交付核对目标、已生成、待审核和缺证据任务，并保留原内容职责。不得因独立图片通过就声明整套完成。

## 九 验证与实施顺序

先实现弱输入存档与来源分析，再实现共用任务准入及直接证据锁，然后贯通套图与 QA。仅放宽包校验而保留后续模板门槛，或仅补说明而不改运行接口，都不算完成支持。

最小行为验收集：

| 输入与任务 | 预期结果 |
| --- | --- |
| 单张清晰正面，关键结构可辨，做原视角外观图 | 不要求凑足多视角；依赖核实后可生成 |
| 同一输入，要求背面扣合特写 | 暂缓该任务并指出缺哪处证据 |
| 模糊图只能辨认品类，要求精确孔位或扣具 | 可保存工程，不伪造完整轮廓或结构锁 |
| 未拆透明包装，轮廓可辨但表面反光 | 外观任务独立判断，材质光泽任务不能借此通过 |
| 不透明包装遮住主体，要求拆包后的产品图 | 不能以去包装指令越过证据缺口 |
| 塑料壳确为产品组件或随售配件 | 不按运输包装自动删除，按本图范围展示 |
| 用户确认有扣具，没有几何或动作依据 | 可保存存在事实，不能批准扣具特写或操作图 |
| 不同扣型的两个 SKU | 不互用结构锁、不套通用线稿；SKU 绑定错误被拒绝 |
| 两份资料对连接方式相互矛盾 | 保留冲突，关键任务暂缓；其他任务继续 |
| 套图中外观任务有依据、操作任务缺状态 | 前者继续，后者保留职责与缺口，不静默减图 |
| 只有文字、来源未知图或锐化后的派生图 | 可存档，不伪装实拍、不提升证据等级 |
| 新证据改变事实或已固定任务 | 受影响判断失效并修订；不抹除原接受记录 |
| 候选额外露出未知结构或把塑料封边画成扣具 | 不能结构通过；纠正或重新规划 |

程序测试验证来源引用、依赖覆盖、状态和版本行为；实图测试验证 AI 是否识别包装、模糊与扣型差异，以及生成结果是否遵守约束。实测需分别记录误放行、误阻断、结构错误与任务表达质量，不以脚本通过推断视觉效果。覆盖不同产品与输入质量后再收紧规则，不预设未经测试的成功率。
