# 日报与周会归档

默认根目录是用户桌面的 `weekMessage`。周会为每周四上午 **10:00（Asia/Shanghai）**，统计周期为上周四至本周三；**周四全天（包括上午）归入下一期**，不按 10:00 拆分日报。**2026-10-15 周会所在周期是 week4（10-08 至 10-14）**，此后每七天递增，跨年不重置。根目录 `.report-config.json` 保存锚点日期和周次，后续以配置为准。历史节假日期间的周会日期和工作覆盖日期分别保存，不按自然周反推或插入空周；缺失历史资料留待补充，不虚构报告。日期按 Asia/Shanghai 和用户指定的汇报日期计算。

```text
weekMessage/
  week4/
    2026-10-15/
      report.md
      report.html
    daily-reports/
      2026-10-08/ ... 2026-10-14/
        上午.md
        下午.md
  week5/                    # 工作日期 10-15 至 10-21，周会 10-22
    2026-10-22/
    daily-reports/
```

既有历史周报不自动重建或改动覆盖范围；已有日报不自动搬移。脚本按工作日期查找旧目录中的日报并去重，同日同一时段存在不同内容时明确报错；补充时沿用找到的既有文件，新文件按新周期归档。周次计算与旧文件的物理位置可以不同，以返回的实际路径为准。

常规周期创建七个日期目录，历史报告按原覆盖日期建目录，仅收到汇报时写时段文件。**只输出 MD 和 HTML，不生成图片。** 历史图片提取全文并核对后，按用户授权删除对应原图；保留不同来源的日期差异说明，不能只留下删减后的摘要。不得删除归档范围以外的图片。

## 上午／下午汇报

- 使用用户指定的日期、时段和内容。日期不明确时取客户端当天日期；时段无法从上下文确定时，只询问上午还是下午。
- 上午通常记录计划、下午通常记录进展，但**以实际内容为准**。用户写“工作计划”时保留计划性质，不能把“测试、开发、对接”改写为“已完成”。
- 日报是周报的数据素材，必须精简。沿用用户格式：标题为 `YYYY.MM.DD工作计划` 或 `YYYY.MM.DD工作汇报`，下面直接列要点；上午／下午由文件名区分，不另加背景、目标、成果、风险、总结等栏目。
- **至少三条，每条一句话，对应一项独立工作**，通常以“测试、优化、开发、研究、完成”等动词开头。只做必要的措辞整理，不扩写实现细节、目的、收益或说明段落；输入已经简洁准确时直接保留。
- 动词必须符合事实：“测试某流程”不等于“测试通过”，“优化某模块”不等于“完成优化”。只有用户明确确认完成时才使用“完成”表达实际结果。
- 若原材料不足三条，可拆分其中明确包含的独立任务；仍不足时请用户补充，不编造任务、不用同义重复凑数。用户仅说明格式或提供示例时，更新规则，不将示例当成真实日报归档。
- 同日同一时段再次提供内容时，读取已有文件，合并补充、去重，明确纠正覆盖对应旧表述，保留其他事实。不另建“上午2”等副本。
- 不自动读取全部聊天、仓库或屏幕。先用用户内容及指定文件；用户要求结合项目记录时才读取相关日期与项目。

日报示例：

```markdown
2026.10.15工作计划

- 优化 A+ 套图生成 Skill
- 测试 LXE_Agent 物流商配置模块
- 测试云驼数据查询流程
```

```text
python3 scripts/report_archive.py paths --date 2026-10-16
# 周四日报归下一期；查询该周四会议报告及覆盖范围时加 --meeting
python3 scripts/report_archive.py paths --date 2026-10-29 --meeting
python3 scripts/report_archive.py daily --date 2026-10-16 --session 上午 --source /absolute/path/draft.md
```

脚本路径相对于本 Skill；从其他工作目录调用时使用绝对路径。可用全局参数 `--root /absolute/path/weekMessage` 指定根目录，放在子命令之前。

## 周四周会汇总

用 `collect --date <周四>` 列出本周期日报和缺失时段，再读取实际文件与上期周报目标。缺文件表示没有记录，不表示当天没有工作。日报不足时使用用户已提供的汇报补充；不伪造日报，也不从周报反推每天上午／下午的成果。

**让负责人快速看到结果。** 沿用组长的分栏样式，通常聚合为 2–3 条业务主线，每条 2–3 个短要点，下阶段通常保留 3 项重点。数量是压缩建议，必要事实不能为了数量删掉。

- 首页一句话写清关键成果和当前卡点。少写实现过程、脚本名、测试条数、文件体积、重复打包等细节，除非本身就是业务成果。
- 通常分本周工作、上期目标、下阶段重点、总结四部分；入职首周没有上期目标时，`goals` 留空，MD 与 HTML 都省略该栏目及完成率，并将后续栏目连续编号。区分已完成、阶段完成、待推进；查询通过不扩大成完整改期通过，规则更新不扩大成实图通过。
- 新报告的日期范围是上周四至本周三，周会文件夹用本周四会议日期；例如 2026-10-29 周会是 week6，覆盖 10-22 至 10-28，10-29 上午及下午均归 week7（11-05 周会）。周四会议的 collect/weekly 查询当期报告，普通 paths/daily 查询当天工作的下一期归属。历史重构保留原周会日期和原文工作范围；已有周会报告仅在用户要求更新时重建。
- 按真实进展去重汇总，不反复罗列成果。没有完成状态记录的事项写“进展待确认”，不能仅凭找不到记录写“未完成”。

```text
python3 scripts/report_archive.py collect --date 2026-10-22
python3 scripts/report_archive.py weekly --date 2026-10-22 --data /absolute/path/report-data.json
```

周报输入 JSON：`headline` 是一句话结论；`work` 是 `{title, summary, items: [{tag, text}]}` 列表；`goals` 是 `{title, status, note}` 列表；`next`、`summary` 都是 `{title, text}` 列表。脚本从同一份数据生成 Markdown 和独立 HTML，正文安全转义，不需联网。模板见 [assets/report.html](assets/report.html)，包含分栏切换、目标筛选、展开全文、打印与明暗切换。

HTML 动效以用户选定的 Motion Smooth Tabs 演示为参考：导航选中块平滑滑动，正文按切换方向退出与进入，容器高度平滑衔接，内部内容再分段出现。整体节奏约 0.5–0.6 秒，保留很轻的收尾回弹，避免快速闪过。连续切换可打断旧动画；打印及系统“减少动态效果”模式保持静态。修改报告样式时只更新 HTML，不改动已确认的正文数据。

默认拒绝覆盖不同内容；需要更新时先读取 `paths` 返回的 SHA-256，再带 `--replace --expected-sha <摘要>`；周报用 `--expected-md-sha` 和 `--expected-html-sha`。该检查防止覆盖并发修改，不是新增人工审批。桌面写入仍遵循执行环境权限。

## 首次设置与交付

```text
python3 scripts/report_archive.py init --anchor-meeting 2026-10-15 --anchor-week-number 4
```

已存在的不同设置不能隐式重置。完成后核对日期归属、计划／成果状态、精简程度和 HTML 显示，回复主要结论和保存路径，不重复贴整份报告。Skill 在用户请求时执行；不代表设置了定时任务或聊天结束钩子，自动提醒与触发需要用户另行明确要求。
