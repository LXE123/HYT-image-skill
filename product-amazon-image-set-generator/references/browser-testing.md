# ChatGPT 网页对话测试

网页按本页执行；其余参考由当前规划、设计、审核或排错需求激活，完整规则和示例保留。已有有效需求包、子图清单或明确任务包时直接复用；资料或职责发生变化、出现具体疑点时再回查来源。不为模拟本地运行而加载脚本状态机和完整 schema。上传归档提供当前任务资料，不等于安装本地技能或增加工具；使用网页实际提供的导入入口与会话工作目录。

## 先检查实际能力

一次检查能否解包/读取资料、实际查看原始产品图片、调用图像生成并向它附加所需产品图。路径文字、文件枚举和搜索摘要不能替代像素或实际传图。工具不可用时一次说明具体限制；不让用户配置本地终端/API，不用 Python 画布、原图拼接或 HTML 截图冒充 AI 生图。

若外部视觉参考无法查看，按 [按需取参](autonomous-design.md#按问题取参) 换来源或用已查看资料继续；不要求用户反复找参考、过验证或逐张重传。实际工具要求续发、额度限制和传图限制必须如实记录，不能靠提示词承诺自动连续执行。

## 规划只保留一份任务清单

复用产品资料与已知要求。混合需求表先执行建包技能的 [intake](../../product-image-project-builder/references/automatic-intake.md)，保留有效事实、原文文案、内容职责和缺口。独立执行环境若可用，设计只接收过滤后的需求及必要原图；同一对话换角色/导出文件不能保证上下文隔离。没有独立能力时说明一次，继续授权任务。

先确定范围和目标图片数，再记录：内容组 ID → 子图 ID → 买家问题/必须证明的内容 → 本图视觉手法/文案 → 状态/输出。七个组不是七张照片：九图种子为 `1+1+2+2+1+1+1`；正常完整 A+ 通常为 13 张，按用户指定数量/范围调整。子图总数必须等于目标；单张或三张小样请求只做其授权数量。按子图 ID 选择下一张，不能按组标题数结束。

A+ 默认按 [页面骨架与七项职责](a-plus-module-layout.md#page-skeleton-and-seven-responsibilities) 融合：产品总览 → 核心卖点/材质 → 结构工艺 → 功能使用 → 配色与尺寸适配 → 佩戴场景。前半段集中说明产品，后半段连续展示场景；配色和适配可合并，识别产品必需的兼容信息可前移。先定本产品的阅读顺序，再分配子图和整套风格。旧九图种子仅为草稿，不能直接照其顺序结束规划；已有批准方案按修订规则处理，不自动迁移。

在同一清单/创意说明中写明每组“承接什么 → 讲清什么 → 引向什么”。产品说明采用“整体定位部件 → 局部与作用 → 有依据的实际使用”；使用图明确起始状态、动作和完成状态，扣具内外特写不能代替操作说明。缺少步骤依据保留缺口。按 [衔接规则](a-plus-module-layout.md#explanation-use-and-continuity) 区分内容递进、相邻背景衔接和实际跨图物体；默认保留完整主体，精确跨边界需真实排版与接缝检查。轮播每张都能独立看懂并接住固定上下模块，不能把必需步骤拆成互斥切换页。新增图优先扩展对应细节、选购或场景轮播，不为凑数改变整页流程。

共享视觉语言，各图按职责采用卖点解释、材质/结构证明、比较、步骤或完整人物场景等表达。具体设计按 [visual direction](visual-direction.md)；单图直接按 [art direction](../../product-single-image-generator/references/art-direction.md)。不默认全部为纯摄影，不把几个无关模块拼为一页。一张图可含服务同一任务的文字、图形和局部细节区；最终 A+ 组装由设计部完成。

整套先在现有 `visual_system` 明确背景主明暗、色系、冷暖、对比度/阴影及字体范围；每张实际生图说明都带上同一份简短规则。逐图可换构图、场景和材质，不能以创意或目录风格为由切换成另一套背景基调。要求统一背景时，不自行安排深浅交替；具体示例见 [共享风格边界](visual-direction.md#shared-boundaries-varied-images)。

## 执行与交付

选择可逆设计方案后自行生成、自查、有限修正。按 [内部试图规则](autonomous-design.md#内部检查后继续授权任务) 继续完整套图；不增加解析、风格、小样和逐图确认门槛。只在必要事实缺失时集中询问，其他任务继续。缺证据任务保留职责和暂缓原因，不编造参数，也不拿无关图凑数。

复用首次建包拆出的事实与卖点，按 [visual direction](visual-direction.md#feature-coverage-and-freedom-of-expression) 判断本图哪些信息通过画面表达、哪些只排文字；同图可混合。不要把全部卖点当作场景生成命令，也不要因无法视觉化就删掉必要说明。文案仍需依据；材质特写不等于透气证明，静态磁扣不等于动作证明。

每次只向图像工具发送当前子图的任务、创意、确切原文文案、硬约束与实际选中图片。生成后按单图技能检查实图，并登记 `PENDING_REVIEW`，再选择未生成的子图。已有候选等待审核不代表应再次生成它。指出某张有问题后直接局部纠正，保留其他结果。

本次 A+ 最终只交付 1464×600 PNG。生成阶段优先约束 **2.44:1（1464:600）横幅**，放在每张提示词开头；参考图、风格与局部排版服从该画幅。当前工具若提供比例/尺寸参数则同时设置，不支持时用明确提示词约束，不虚构参数或自动切换到 API。把产品、人物动作和必要文字安排在画幅内的可保留区域。每张生成后仍必须执行代码导出，不能只依赖模型输出尺寸或手填尺寸标签；生成原文件另存，按单图技能的 [代码导出流程](../../product-single-image-generator/references/state-and-contract.md#mandatory-a-code-export) 调用 `finalize_a_plus_image.py`，再审核和交付最终文件。原图比例一致时保留完整画面、直接等比例缩放，不必传 `--keep-box`；已经是目标尺寸也通过脚本另存并记录导出信息。网页也执行相同代码步骤；有 Python 环境时使用随包脚本，不能用截图或声明已处理代替实际文件导出。

比例不同时，根据实际原图给出包含全部必要内容的 `--keep-box`，裁剪后等比例缩放，不固定居中裁剪。放不下则重做构图或重新生成，禁止分别拉伸宽高、补边或裁掉文案凑尺寸；小图确需放大时显式使用 `--allow-upscale` 并记录。缩小后检查细字、细线和纹理是否丢失，放大后检查模糊，尺寸达标不代表清晰度通过。代码/Pillow 不可用时只交原始候选并标注代码导出未完成，不把它当作合格 A+ 成品。不自动制作手机版、其他画布或未选语言分版。

新 A+ 任务要求裁剪前检查：使用 `candidate_qa.py --init --source-image <包内原图路径>` 创建原图 QA，按 `SOURCE_IMAGE` 坐标标注实际产品/指定细节、文字和保护区域；再按 [完整代码导出步骤](../../product-single-image-generator/references/state-and-contract.md#mandatory-a-code-export) 查询拟裁剪框。脚本会投影到目标画幅，检查必要内容保留及明确的排版约束。根据实际原图和拟裁剪范围检查主体大小、文案可用性和重心，记录对应裁剪框及观察后，使用 `--package/--contract/--review` 导出。检查不确定或失败时不导出，不靠改 PASS 绕过。导出后另建最终图 QA，不能复用原图坐标或把原图检查当作最终验收；这些是内部检查，不新增逐图用户批准。

区域观察沿用助手/人工标注，不接入 SAM 2 或安装模型；点或粗框只在目标歧义时辅助看图，不作为检测结果。

交付前把实际候选并列查看背景明暗、色温、对比度/阴影和字体是否连贯；偏离共享范围的图片局部纠正，不因单张好看就认定整套统一。沿用 `design_quality` 记录观察，不新增评分表或风格确认流程。

构图检查区分目标布局和最终图片中的实际区域，按单图技能的 [构图观察及报告复用](../../product-single-image-generator/references/visual-quality.md#actual-composition-and-review-reuse) 记录产品/指定细节、实际文字区与不确定项，绑定最终文件哈希。特写不套用完整商品入画规则；只有当前任务明确要求的文案独占区才检查侵入。代码验证标注与显式几何条件，不代替实际看图或设计判断。没有代码环境时也保留同样的候选版本和观察依据，不声称脚本已运行。

同一图片、规格、参考依据和审核规则没有变化时复用已记录结论；已有失败就修正，边界不确定就保留待复核，不反复让视觉模型重判同一张图。更换图片、裁剪或排字后检查新的最终文件；中断时先核对已有输出，再决定是否需要重新生成。用于并列比较的样图也需记录版本，比较对象变化后更新相关观察。原始样图和派生测试负例分开标识，助手标注不等于人工验收。

最终提供各图片文件和简短 `TEST_RESULT`：目标/计划/已生成/暂缓数量、实际尺寸、所用来源、修正次数、用户输入/续发次数及原因、QA 与剩余问题。候选集中展示并可打包下载。只有真实反馈才能记人工接受；本地记录通过、网页出图完成与视觉验收分别报告。
